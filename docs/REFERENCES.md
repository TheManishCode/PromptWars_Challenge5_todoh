## What was verified in a clean install (2026-11-04) and what was not
Checked: a new virtual environment (Python 3.14, `uv`) installed `.[browser,documents,dev]` from a clean copy of the repository at `16fa278`. Docling 2.146.0, Playwright 1.64.1 and CPU torch were installed; the models were
downloaded from scratch into an empty `HF_HOME` (about 6 minutes). Then, in that environment: the browser tests rendered pages with the system Chromium (20 passed); a real Word quote and a real PDF were read through
Docling in the sandbox into the right lines and totals (the real-engine tests in `tests/test_documents.py`); and the full suite ran.

This found three things, all fixed in `e56b75b` and the commit after it:
- `warm` left the OCR engine's weights (the `.pth` files in `site-packages`) unfetched, so the first PDF in a clean install failed with "could not be read". `warm` now converts a one-page sample with OCR forced.
- The document sandbox was not network-isolated: that missing download ran from inside it. The reader is now shut in at the strongest of four levels the machine supports (`documents/isolation.py`): bubblewrap (no network, no other server files), Landlock plus a socket filter (the same, with no privilege needed), `unshare -rn` (network only) and a socket filter alone. With one weight file deliberately removed, the sandboxed PDF failed and did not fetch it again.
- A test (`tests/test_state.py`) used the wall clock for a deadline that the test clock set 5 days after 30 Oct, so it failed from 4 Nov.

Isolation was checked with the real Docling engine (a real PDF and Word file give the right lines at every level) on this Linux machine, and in the `python:3.14-slim-bookworm` image run as the compose file does (non-root, `--cap-drop ALL`, `no-new-privileges`, read-only): there `unshare` and bubblewrap are unavailable, Landlock plus the socket filter works, the reader cannot connect to a loopback listener or read a data file or `/etc/passwd`, and shared mode accepts that level. The `confined` level grants `/proc/self` and two machine-description files only, not all of `/proc`: before this was tightened, Landlock would have allowed reading another same-user process's `/proc/<pid>/environ` wherever the host's `ptrace_scope` permits it (the host here had Yama at 1, which hid the problem). The socket filter also refuses the whole x32 system-call range on x86-64: an exact match on `socket` (41) was bypassed by the x32 number 0x40000029, which opened a working socket under the first version of the filter (shown on a kernel with `CONFIG_X86_X32_ABI=y`, and in the container; the new test fails without the range rule). A child the reader starts is shut in the same way (tested for contained, confined and no-sockets), and if the restrictions cannot be applied when a file is read, the reader does not run. Limits: the server's command line and environment are readable by the reader at the `network` and `no-sockets` levels (neither is accepted in shared mode), so never pass a secret as a command-line argument; `contained` and `confined` refuse it (tested). `stat` of a hidden path still shows that it exists; the CPU directory under `/sys` and `/proc/cpuinfo` and `/proc/meminfo` stay readable; the socket filter and Landlock were tried on x86-64 only; kernels older than 5.13 have no Landlock.

Not verified: Playwright's own downloaded browsers (the system Chromium was used); any machine without `unshare` or user namespaces (locally the reader still runs there, with the Hugging Face offline flags only, unless `EVENTMATE_REQUIRE_NETLESS=1`; in shared mode it refuses to start and never reads); arm64;
other operating systems and CPU types; GPU torch; Python 3.9. Installing with plain PyPI timed out on a large CUDA wheel at the default `uv` timeout; the CPU torch index and `UV_HTTP_TIMEOUT=900` were used. No re-implementation was diffed against its upstream
source: the claim is that the idea was read and written again with credit in the docstring and covered by this project's own tests. The licence questions (Dify's terms; the two repos whose licence was not checked) stay open before any release.
